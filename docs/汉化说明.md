本仓库是 [egormagurin/EldenRingMap](https://github.com/egormagurin/EldenRingMap)
的简体中文分支，由 **MiyauchiRenge** 维护。这份文档说明**改了什么**，
以及为什么这么改；安装与使用见 [README.md](../README.md)。

改动分两部分：**汉化**（界面与标记名）与**技术改动**（图标管线、工具整理）。
下面每一条都对应仓库里真实存在的文件，不是计划。

## 二、技术改动

### 物品图标：五张 `EquipParam*` 表的图标字段

界面右侧的每个道具标记都显示**它自己在游戏里的图标**，编号来自
`regulation.bin` 的五张参数表（`tools/extract_items.py` 的 `ICON_OFFSETS`）：

| 参数表 | 字段 | 宽度 | 物品类别 |
|---|---|---|---|
| `EquipParamGoods` | `+0x030` | s32 | 道具：铃珠、卢恩、锻造石、种子、露滴、骨灰、消耗品… |
| `EquipParamWeapon` | `+0x0BE` | **u16** | 武器与弹药 |
| `EquipParamProtector` | `+0x0A8` | **u16** | 防具 |
| `EquipParamAccessory` | `+0x026` | **u16** | 护符 |
| `EquipParamGem` | `+0x004` | **u16** | 战灰 |

关键点是**后四个字段只有 2 字节**。按 4 字节读会把邻居两个字节折进高位，
邻居非 0 的行就会显示成**别人的图标**（例如防具行显示成某个护符）。
现在的读法与外部对照表逐条核对过：护甲 50/50、武器 133/133、弹药 69/69、
护符 73/73 全部一致，剩下的差异全部是 DLC 新增行（那张对照表停在 DLC 之前）。

**防具的 `+0x0A8` 具体是哪个字段**：按 Paramdex 的定义，`EquipParamProtector`
的 `iconIdM` 在 `0xA6`、`iconIdF` 在 `0xA8`，也就是本分支读的是**女性图标**。
全表 838 行里只有 12 行 `iconIdM != iconIdF`，而这 12 行**没有一个是地图上的
拾取点**（逐个反查过：63 个防具标记受影响 0 个），所以这一选择在数据上没有差别。

> 名称与图标是两件事：名字来自 `item.msgbnd.dcx` 的名称表，
> 位置来自 MSB 的宝箱事件 → `ItemLotParam_map`，图标来自上表。

### 图例改用物品自身图标

左侧分类行原本用捆绑的分类图标（Map-for-Goblins 的 PNG）。现在每个分类行
优先显示**该分类下物品自己的图标**（锻造石按等级、黄金卢恩按级别一眼可分），
分类图标资源随之删除，`legendSwatch()` 在拿不到图标时退回彩色圆点。
个别分类的推断图标不合适时，用 `web/js/app.js` 的 `CAT_ICON` 明确指定
（例如防具行用白金之子头罩 `14800`，而不是推断出的粪金龟头盔）。
这类"没有标记引用、但图例要显示"的图标列在 `tools/extract_icons.py` 的
`EXTRA_ITEM_ICONS` 里，重新提取时不会丢。

### 铃兰按等级分类；分类标签与游戏译名对齐

- **铃兰（Glovewort）原本是一行 49 个标记**，混着墓地铃兰【1】【5】-【9】和
  灵依墓地铃兰【5】-【9】。图例行图标取"该分类里最常见的那个 iconId"，平局下
  只会显示某个固定等级（墓地铃兰【7】）——和防具行显示粪金龟头盔同一个毛病。
  现在像锻造石那样按**家族 + 等级**拆开：`glovewort_grave_1`…`_9`、
  `glovewort_ghost_1`…`_9`，外加两行无等级的"大朵"。
  有地图标记的 13 行会显示（11 个等级 + 2 个"大朵"）。
  剩下 7 个等级——墓地【2】-【4】、灵依【1】-【4】——**地图上没有放置点**
（改写自早先的说法「只有商店一个来源」：复核后发现它们同样是 `ItemLotParam_enemy` 里的
可刷掉落，只是没有被放置到地图上；参考项目 catalog.json 里这 7 条的 `enemy_drop` 来源与之一致）：
  `ShopLineupParam` 里它们各有一行（`#101830`-`#101841`，`equipType=3`，价格
  1200/1600/2400/1200/1800/2400/3600），而没有任何**被地图放置**的 lot，
  所以地图上本来就找不到。`restrictCatsToData()` 把这类空行丢掉，
  而不是显示成 0/0。
  （18 个等级**全部**在商店出售，价格 800–12000；只有"大朵"两种不在商店表里。）
- **标签按游戏译名修正**：铃兰两行原写作"陆生海鞘/大朵陆生海鞘"（另一种素材），
  另有 `whetblades` 砥石小刀→砥石刀、`lost_ashes` 丢失的战灰→失力战灰、
  `prattling_pates` 多话的帕特→唤声泥颅。判定方法是把 **101 个分类**（加上商人是
  102 个）的标签与它们实际装的道具名做全量比对（道具名取自游戏 `zhocn` 文本）。

### 位置说明：从"交界地"改成游戏的地区名

界面上标记的位置原本只有地图层（`M00` → "交界地"，`M01` → "地下"，`M10` → "幽影之地"），
对找东西没有帮助——三千多个道具全在"交界地"。

- 数据：`WorldMapPlaceNameParam` 是大地图上那几块地区名的来源（宁姆格福 / 湖之利耶尼亚 /
  亚坛高原 / 盖利德 / 巨人山顶 / 安瑟尔河 / 希芙拉河 / 深根底层 / 幽影之地）。
  它每行给出所属的**地图碎片**（`worldMapPieceId`，碎片的 `openTravelArea` 已是主图像素）
  与地区分组（`areaNo`：10/60 地面、12 地下、61 DLC）。
- 产出：`tools/build_markers.py` 新增 `build_regions()`，写出 `data/regions.json`
  （名字、所属地图层、矩形，`default` 标记"没有矩形的那一块"）。
- 判定：`web/js/app.js` 取**距离最近的地区矩形**（在矩形内即 0，超过 400 主图像素就不算
  "这里"），没有就近的矩形时回落到 `default`——那正是**开局就送、因此没有地图碎片的
  宁姆格福**，也就是"本层里没被别的地区认领的部分"。
  矩形是碎片的揭示范围、比地区本身窄，所以还加了一条：**最近地名的名字里若出现地区名**
  （"利耶尼亚湖（湖边）" 与 "湖之利耶尼亚" 共享"利耶尼亚"），以名字为准——那一处
  按矩形会落进宁姆格福，而赐福名说明它在利耶尼亚。
- 显示：提示气泡与搜索结果的 `职业 · 位置` 一行现在是 `地区（最近地名）`，
  例如 `道具 · 湖之利耶尼亚（彼鲁姆教堂）`；最近地名就是游戏自己的赐福/据点名，
  且限定同一地图层（地下与地面共用主图坐标）。当标记自己的名字里有这个地名时
  （赐福本身就是地名、商人名字里已带地点）不再重复。
- 地区表随 `data/regions.json` 一起下发（`/api/markers`），所以**实时模式下的
  位置**也能显示所在地区；文件不存在时界面回落到原来的地图层名，不会空白。
- 交叉验证：判定结果与社区商人清单吻合（"East Altus Plateau - Hermit Merchant's Shack"
  → 亚坛高原，"North Caelid (Dragonbarrow) - Isolated Merchant's Shack" → 盖利德）。

### 社区格式文档改为运行时获取（并接进 Setup）

原版把 Paramdex 的参数定义、ER-Save-Lib 的旗标表、Map-for-Goblins 的物品 id
列表直接放在仓库里。本分支**不提交这些文件**（它们属于那三个项目，不是游戏素材，
也不是本项目的成果），改由 `tools/fetch_docs.py` 在安装时取一次，
`.gitignore` 挡住它们以免误提交。详见 [data/README.md](../data/README.md)。

这次修掉了一个真问题：**`fetch_docs.py` 写好了，却没有任何脚本调用它**——新克隆的仓库
里 `data/paramdefs/` 是空的，`build_markers.py` 会直接报错。现在它是 `Setup.bat` 的
**[2/9] 步**（`setup-linux.sh` 的 [1/8]，在读取任何 param 之前），失败时给出明确提示
与手动下载地址。另外两个定义**上游没有**（实测 404，取自 Paramdex）：

- `NpcParam.xml` —— 商人的种类名要靠它读 `nameId`；
- `WorldMapPlaceNameParam.xml` —— 上面第 5 节的地区名。

`build_markers.py` 缺 `WorldMapPlaceNameParam.xml` 时仍然能跑完，只是跳过
`data/regions.json` 并打印提示；`extract_items.py` 缺 `NpcParam.xml` 时退回实测偏移
`+0x0C`（两条路径已验过输出逐字节相同）。

### 同一点位上的多个标记

地图上 3 像素内有 **321 组**重叠（完全同一坐标的 258 组、667 个标记），成因三类：

* **新加的掉落压在给予者身上**：Boss 掉落的位置本来就是那个 Boss（103 组含 Boss 掉落），
  一次性奖励也一样压在角色身上；
* **同名采集物叠在一处**：最多一处 12 个拉答果实（各自有旗标，是不同拾取事件）；
* **上游本来就有的“一地多标”**：同一个地方被赐福 / 据点 / 派生地标各记一次。

而 `pick()` 只返回最近的那一个，叠在下面的**根本点不到**；上游的 `merge_colocated()` 又只
合并“同分类 + 同名”，并明确注明不合并 Boss 与拾取点。所以本分支做了两件事：

- **同点位列表**：`pick()` 改成按屏幕距离收集一组（阈值 6 屏幕像素，随缩放自然变化），
  卡片里多一行“此处还有”——每个是一条可点的按钮，点了就把卡片切到那个标记。完全同点的
  标记在任何缩放下距离差都是 0，所以永远在同一组；稍微错开的一放大自然分开。列表最多列
  6 条，其余写“另有 N 个”。（后改为：列出全部条目、**顺序固定**，当前项用方框标出而非消失，条目多时列表内滚动。）
- **聚合豁免 Boss**：`cluster()` 把 boss 单独留在气泡之外、画在气泡之上，理由是 Boss 是
  地点而不是杂点，而且“要到最后才能点亮”的那个不该藏在读作“未发现”的气泡后面。

仍然待做的：**同名采集物合并**（与“采集物单列 + 不计进度”一起做最合适）。参考项目
（ChenxiLiu-code/EldenRingTool，LGPL-3.0）用世界坐标 + 屏幕像素预算聚合、并且豁免 Boss，
但它**没有**解决“同一点不到”——它的掉落标记同样落在敌人坐标上，QML 里也没有同点列表。
### Boss 掉落的人工核定归属

`data/boss-drop-overrides.json` + `extract_items.py` 里的应用逻辑。原因：Boss 击杀奖励常由
EMEVD 直接按 lot 发放，脚本看不出归属；自动流程（EMEVD 邻域 + 名字匹配）覆盖不到这一类。
`剑骸大剑`（武器 4100000）只在 map lot 10800、旗标 510800，且没有任何 NpcParam 指向它，
所以既不是拾取点也不是怪掉落。核定条目只补"归哪个 Boss"，lot/旗标/物品名仍全部来自游戏；
标记落在该 Boss 坐标上，`via: curated`，`note` 记录来源。 1 条（狮子混种）。

因此 Boss 掉落从 152 → **153**，标记总数 4,798 → **4,799**。

### 隐藏启动器与服务的停止条件

`Start Map.vbs`：用 `WScript.Shell.Run(cmd, 0, False)` 以窗口样式 0 运行现有的
`Start Map.bat`，输出重定向到 `logs\map-server.log`（该目录已加入 .gitignore），并把
`pause` 的输入接到 NUL——否则隐藏窗口里的报错分支会**卡在 pause 上**，变成一个看不见也关不掉的
进程。参数原样透传，所以 `--live` / `--lan` 都能用。

配套的服务端（`server/index.js`）：

* 每个请求刷新 `lastSeen`；`GET /api/ping` 就答心跳；
* `POST /api/bye` 记录 `byeAt`，看门狗在"距 bye 与距最后请求都超过 8 秒"时才退出——刷新页面
  同样触发 `pagehide`，靠这 8 秒宽限区分"刷新"与"关闭"；
* 兜底 `--idle-exit`（默认 150000ms）无任何请求即退出；`--no-idle-exit` 关闭该行为；
* `/api/bye` 校验 Origin 必须是 localhost/127.0.0.1/::1，防止别的网页调用它关服；
* 看门狗定时器 `unref()`，不阻止进程正常退出。

客户端（`web/js/app.js` 的 `startKeepAlive()`）：启动时立刻 ping 一次，之后每 5 秒一次；
`pagehide` 时 `navigator.sendBeacon('api/bye', '1')`。

实测（三例，均已通过）：
  * `--idle-exit 6000` 不访问页面 → 进程自行退出、端口关闭；
  * ping 之后 `POST /api/bye`（带 localhost Origin）→ 应答 `{"ok":true}`，约 8 秒后进程退出；
  * `cscript //nologo "Start Map.vbs"` → 8099 正常监听、`logs\map-server.log` 写入启动信息、
    node 进程的主窗口句柄为 **0**（即无窗口）。
