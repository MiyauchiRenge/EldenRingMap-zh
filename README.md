# 交界地地图

[English](README.en.md) · [游戏机制](docs/机制.md) · [实现与流程](docs/实现.md)

艾尔登法环（Elden Ring）的本地交互式地图，中文优先，由 **MiyauchiRenge** 维护。
标记、分类与进度全部由本机游戏文件与存档生成：程序只读，不修改游戏，也不修改存档。
引擎来源与许可说明见文末「五、来源、授权与免责声明」。

---

## 一、功能

* **交互式大地图**：地表、地底、幽影地各层，支持缩放、平移与地图层切换；
* **标记与分类**：赐福、地标、Boss、地图碎片、道具、采集点、可刷点、商人、角色掉落、Boss 掉落、
  事件给予、商店货架、任务与事件奖励等；每个分类一行，可勾选并统计进度，行图标使用物品自身图标；
* **进度口径**：区分一次性获取与可重复获取。可刷新的采集点按"处"显示且不计入完成度，一次性节点
  计入；规则由数据下发（见 [docs/实现.md](docs/实现.md) 第 3 节）；
* **同点位多标记**：同一位置的多个标记可逐条选择（卡片内"此处还有"列表），Boss 不参与气泡聚合；
* **地区与最近地名**：标记与玩家位置均显示游戏自身的地区名与最近地名；
* **存档联动**：读取存档中的已拾取状态与角色最后位置，用于勾选、进度与玩家标记（只读）；
* **两种启动方式**：`Start Map.bat`（可见控制台）与 `Start Map.vbs`（隐藏窗口）；页面关闭后服务自行退出；
* 简体中文界面，名称取自游戏官方中文文本。

## 三、实现要点

* **采集点**：地图资产部件名形如 `AEG{xxx}_{yyy}_{instance}`，其中 `AEGxxx_yyy = xxx*1000+yyy` 为
  `AssetEnvironmentGeometryParam` 的行号；该行 `+0xB8` 指向 `ItemLotParam` 的 lot，`+0x3C` 为寿命位
  （`0x60` 一次性 / `0x40` 可刷新）。扫描 1,248 张地图的 621,538 个部件后得到 19,263 个采集点，
  其中一次性 1,661 个，并以存档的 `FOEG` 区块（仅记录永久拾取）逐条复核。
* **存档世界状态**：存档槽在事件旗标之后含两个区块：`MOEG`（已破坏或已拾取物件）与 `FOEG`
  （永久拾取的一次性节点）。记录长度 8 字节：`key = instance << 15 | state`、
  `model = 10000000 + AEG id`，按地图分段。
* **任务与事件奖励**：446 条"旗标已设置但没有任何世界物件引用"的 lot，逐条取证判定（事件指令、事件记录、
  商店货架、lot 地图位、开局段、无引用），其中 23 条落到坐标，423 条仅登记判定与理由。
* **验收结果**：`FOEG` 已拾取节点 321/321 均可在地图上找到；存档旗标漏点 0；采集物图标 114/114 完整；
  坐标核对误差 0.2 像素。幽影树碎片 46 个点位 / 50 个物品，灵灰 23 个点位 / 25 个物品
  （部分点位一次给出两个）。

字段位置、判定方法与验证数字见 [docs/机制.md](docs/机制.md)；已知限制见文末「五、来源、授权与免责声明」。

## 四、安装

```
1. 运行 Setup.bat（数据全部在本机生成，17 步）
2. 运行 Start Map.bat（可见控制台）或 Start Map.vbs（隐藏窗口）
3. 在浏览器打开提示的地址
```

仅支持 Windows，需要 Node.js 18+ 与 Python 3（Python 仅用于安装阶段）。服务默认仅监听本机，
`--lan` 可开放到局域网。详细步骤与故障排查见 [docs/实现.md](docs/实现.md) 第 6 节。

### 数据与判定

* **补齐懒加载层的分类行（采集点分类此前全部不可见）**：`restrictCatsToData()` 只为 `EXTRA_CATS`
  （6 项）补行，而按物品拆分的 79 个 `gather_*` 分类只出现在层策略里，因此没有任何 CATS 行；
  `state.enabled` 只由 `Object.keys(CATS)` 建立、`visibleMarkers()` 又只看 `state.enabled`，
  结果是采集点层 **18,837 个标记按构造无法显示**（其中 `gather_20720` 一类就有 3,395 个），
  侧栏也看不到这些行——与本文第三节"采集点按物品各成一类"不符。现改为：注册表标为 `lazy` 的层的
  分类在启动时即建有行（`LAZY_CATS`，随 `data/layers.json` 下发），沿用 `gathering` 的颜色与半径，
  归入同一分组，且**默认不勾选**（与 `gathering` 一致，避免一开就是一万九千个点）；
  `catLabel()` 增加回退链（手写标签 → i18n 里的裸物品键 → 标记自身的游戏名），
  中文材料名因此直接取自游戏文本。实测：CATS 行 122 → **201**，无行标记 **18,837 → 0**，
  中英行名分别解析为「遗迹石」「罗亚果实」与 "Ruin Fragment"、"Rowa Fruit"。
  未给 `unplaced`（423 条已登记但无坐标的奖励）建行：它的标记没有任何坐标，
  空行只会误导，改由下方「已登记（无坐标）」列表呈现。

* **任务与事件奖励逐条判定（446 条）**：`tools/extract_quest_rewards.py` 改为证据驱动，不再由 lot 编号推断
  地图。判定结果：商人货架出售 71 条、lot 编号含地图位 20 条、事件脚本数据记录 1 条、开局即持有
  （旗标 60000–60999 段）7 条、游戏数据无引用 347 条。其中 23 条落到坐标（货架所属商人、对应地图的
  Boss 或赐福），其余 423 条将判定、旗标段与理由写入 `data/quest-rewards-unplaced.json`。
  证据与校验：EMEVD 记录形状 `(type, entity, entityFlag, lot)` 在已知由事件发放的 lot 上验证为 199/199；
  `ItemLotParam_map` 编号规律 `<lead><area:2><grid:2><seq:4>` 在已落点的 6,958 个 lot 中命中 1,669 个
  （旧读法 `// 10_000_000` 命中 18 个，是旧版无法落点的原因）；小额 lot 不参与数值检索
  （lot 2000 在事件文件中命中 9,929 处常量）；商店判定要求 `equipType` 与物品类别一致
  （未作该检查时误判为 88 条，收敛后为 71 条）。
* **层契约与注册表**：新增 `tools/erlib/layers.py`，以单表声明每层的文件名、生成工具与参数、
  是否必需、进度口径（`counts` / `spots`）与下发方式（`initial` / `lazy`）。全部抽取器改为通过
  `write_layer()` / `write_raw()` 写出（16 处）：统一 `{"locales","markers"}` 结构、键排序、LF 换行、
  紧凑分隔符、临时文件加替换。实测：同一工具连续两次运行输出逐字节相同；数据层总体积
  9.53 MB → 8.54 MB（−10%）。
* **`Setup.bat` 不再漏跑数据层**：注册表自检（`python tools/erlib/layers.py check`）发现安装脚本缺少
  4 个数据层（EMEVD 奖励、任务与事件奖励、商店货架、数量标注），已补齐，并在安装末尾自动执行自检；
  同时移除写死的步骤编号，新增数据层无需重新编号。
* **进度口径改由数据下发**：`data/layers.json` 声明每个分类所属层与统计口径。客户端优先据此判断，
  缺少该文件时回落到 `gather_*` 前缀规则。实测：两种规则在 202 个分类上无差异，其中 35 个分类同时
  出现在点位层与计数层（`smithing_stone_*`、`glovewort_*`、`somber_stone_*`），按计数层计，
  与客户端原有逻辑一致。
* **商店货架归属**：货架为 `ShopLineupParam` 中由说话脚本声明的一段连续行，形式为
  `bank 1 cmd 22 (first,last)` 或 `bank 6 cmd 2147483610 (flagA,first,last,flagB)`，后者的旗标由地图号
  拼接（`m60_43_53` → `1043530701` / `1043532700`）。据此归属：8 行货架中 6 行落到具名商人
  （5 行为流浪与遁世等商人自述的行段，1 行为幽影之地的休里耶），其余 2 行无脚本声明，按无归属记录。
  商人计数为 20 个商人 / 21 个标记：商人 `32001520` 在原版数据中有两处放置（远眺岛与利耶尼亚湖湖边，
  各带一头驮马），与 20 段货架一致。
* **铃珠后处理接入安装流程**：`tools/dev/fix_bell_positions.py`（按 `NpcParam` 的 lot 将 19 个商人铃珠
  移至主人坐标，`via: bell-owner`）与 `link_bell_bearings.py`（为 20 个商人标记补充 `dropsBell` /
  `dropsBellPx`）此前未被应用到发布数据，而更新记录已记载该字段存在。现已实际执行并写入
  `Setup.bat` 第 16、17 步（注册表同步登记，自检仍为 0 处未声明调用）。实测：仅 `npcs.json` 与
  `drops.json` 变化，其余 19 个数据文件逐字节不变；商人数仍为 21，21 个名称全部不变；连续两次运行
  结果一致。`tools/dev/rename_merchants.py` 已删除：该工具是商人命名的过时重复实现（旧式
  "种类·地点"及仅其读取的过滤表），实际命名由 `extract_items.py` 的"种类（最近赐福）"完成。
* **Boss 掉落人工核定表**：保留 `data/boss-drop-overrides.json`（不进仓库）机制，条目仅补充归属的
  Boss，坐标落在该 Boss，`via: curated`。当前本机无该文件，`boss-drops.json` 的 152 条全部来自脚本
  判定（`via` 仅有 `name` 与 `script`）。
* **采集点寿命位**：`AssetEnvironmentGeometryParam` 的 `+0x3C` 为寿命位（`0x60` 采集后不再生、
  `0x40` 休息后再生、`0x00` 无对应世界节点）。以存档 `FOEG` 区块复核：其列出的 44 行全部为 `0x60`，
  无例外；第二份存档（1,669 旗标）结果一致。采集点据此分为一次性 1,661 个与可刷新 17,602 个，
  仅一次性计入完成度。
* **同点位列表与 Boss 聚合豁免**：`pick()` 改为按屏幕距离收集一组（阈值 6 屏幕像素），卡片增加
  "此处还有"列表，逐条可点、顺序固定、当前项以方框标示；`cluster()` 将 Boss 排除在气泡之外。
  实测：按同地图层、像素距离 ≤ 3 分组，28,177 个有坐标标记形成 2,651 组重叠（涉及 8,025 个标记），
  其中 886 组为完全同坐标。
* **地区名与最近地名**：新增 `WorldMapPlaceNameParam` 解析与 `data/regions.json`（9 个地区及矩形），
  标记与玩家位置显示"地区（最近地名）"。判定取最近地区矩形（超过 400 主图像素不计入），
  名称含地区名时以名称优先。
* **分类与标签修正**：锻造石与铃兰按类别与等级拆行，卢恩同此；标签按游戏译名修正
  （砥石小刀 → 砥石刀、丢失的战灰 → 失力战灰、多话的帕特 → 唤声泥颅等），判定方式为将 101 个分类的
  标签与该分类实际包含的道具名全量比对。
* **物品图标**：使用五张 `EquipParam*` 表的图标字段，后四个字段宽度为 2 字节，按 4 字节读取会显示
  其他物品的图标；已与外部对照表逐条比对（护甲 50/50、武器 133/133、弹药 69/69、护符 73/73）。
  图例改用物品自身图标，需要固定的四行记录于 `CAT_ICON`。
* **商人数量与命名**：20 个商人 / 21 个标记（`c3200` 部件 29 个，其中 8 个指向没有驮马的占位行）；
  名称取同一 master 内最近的赐福（≤ 300 px），超出范围时取最近的非 Boss 地标，人工指定优先。
* **子图坐标**：仅对 `place()` 无法投影的地图（如 `m10_01_00`）做母图坐标平移；可正常投影的地图不再
  平移，修正了一处商人标记偏移 256 px 且地形高度不符的问题。

### 传输与性能

* **响应层与压缩**：新增 `server/lib/respond.js`，JSON 与文本按 `Accept-Encoding` 选择 brotli 或 gzip，
  编码结果按内容 ETag 缓存；带 ETag，条件请求返回 304；`/tiles/**` 与 `/icons/**` 缓存一天，
  其余为 `no-cache`。实测：首屏标记文档 8,564,838 B → 1,560,023 B（未压缩）→ 173,122 B
  （brotli，−98%）；`js/app.js` 93,960 → 30,282 B、`js/i18n.js` 30,786 → 8,293 B、
  `css/app.css` 17,659 → 4,742 B；重复请求命中 ETag，返回 304 与 0 字节。
* **重层懒加载**：注册表新增 `client` 字段（`initial` / `lazy`），`followup`（855 KB）与
  `gather-nodes`（6.15 MB）标记为 `lazy`，服务端提供 `/api/layer/<id>`，页面首帧后并行获取并合并，
  失败时仅缺少对应标记。首屏标记数 28,156 → 5,970；懒加载层压缩后分别为 385,863 B 与 55,417 B。
  首屏数据含 121 个分类而策略文件声明 202 个，侧栏与勾选状态按策略文件建立，采集点分类不会因数据
  延迟到达而被剔除。
* **渲染开销**：以真实数据驱动实际绘制回调测量，全部数据层（28,177 个标记、201 个分类）为 5.09 ms/次，
  首屏（5,971 个标记）为 1.93 ms/次，即懒加载将首屏绘制开销降至约 38%（Node 与模拟 canvas，
  未进行实际栅格化，为下限值）。
